# REVIEW.md

Defects found in the starter `app/main.py`, all fixed in the submitted version.

| # | Where | What is wrong | How you'd notice it | How I fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Late if whole minutes > 10, so 09:40:30 gives 10 min and is treated as on time; R2 says *strictly more than 10:00*. No truncation to whole seconds. | Punch-in at 09:40:01 must give 10, starter gives 0. | Work in seconds: late only if `seconds > 600`, then `seconds // 60`. Instants truncated to seconds at the API boundary. |
| 2 | `compute_late_minutes` | `punch_in.replace(hour=...)` uses the punch-in's own date and time zone (naive server-local time), not the IST attendance date. Overnight shifts break (a 03:00 punch-in is "late" against the wrong day). | Server in UTC: every IST punch-in is shifted by 5h30. | `shift_start_at(date, shift_start)` builds an IST datetime from the R1 attendance date. |
| 3 | `compute_work_hours` | `round()` is banker's rounding on a float; R4 wants half-up. | 9h 0m 18s = 9.005 h: starter gives 9.0, rule says 9.01. | `Decimal(seconds)/3600` quantized with `ROUND_HALF_UP`. |
| 4 | `compute_overtime` | No 30-minute minimum (R3); no overnight handling (end is next day); `.replace(hour, minute)` keeps stale seconds/microseconds; takes a string date and hard-codes IST on one side only. | Punch-out 5 min after shift end returns 5 instead of 0; 22:00-06:00 shift gives 0. | `shift_end_at()` adds one day for overnight shifts; floor minutes, returned only if >= 30. |
| 5 | helpers + endpoints | Half day (R5) and `overtime_minutes`/`half_day` are never computed: there is no punch-out. | Missing endpoint. | `derive()` computes all four derived fields in one place, reused by punch-in, punch-out and PATCH. |
| 6 | `create_employee` | Check-then-insert race, no unique index: two parallel creates both succeed. | Fire 10 identical POSTs in parallel; several 201s. | Unique index on `emp_code`; `DuplicateKeyError` becomes 409. |
| 7 | `create_employee` / `EmployeeIn` | No validation: bad `emp_code`, bad email, `shift_start == shift_end`, `joined_on: "banana"` all accepted; all fields are free strings. | POST `joined_on="2026-02-30"` returns 201. | Pydantic patterns/lengths from the OpenAPI schema, real-date check, start != end check, all giving 422. |
| 8 | `create_employee` | `created_at = datetime.now()` is naive server-local time and the response returns a raw datetime instead of epoch ms. | Response `created_at` is an ISO string, stored value depends on server time zone. | Stored as aware UTC, returned as epoch milliseconds. |
| 9 | `list_employees` | `skip = page * page_size` skips the first page (should be `(page-1)*page_size`). | `page=1` returns employees 21-40. | Fixed formula. |
| 10 | `list_employees` | `total` ignores the department filter; no sort, so paging order is undefined; `page=0`, `page=-3`, `page_size=100000` accepted. | `department=Ops` shows `total` of everybody. | `count_documents(query)`, `sort emp_code`, `Query(ge=1)`, `page_size` 1..100 (R10). |
| 11 | `punch_in` | Unknown employee: `emp` is `None`, `emp["shift_start"]` raises TypeError, a 500. | POST an unknown `emp_code`. | Explicit 404 before anything else. |
| 12 | `punch_in` | Check-then-insert race: two simultaneous punch-ins both pass `find_one` and both insert (duplicate day). | Parallel requests give two 201s. | Unique `(emp_code, date)` index; insert and catch `DuplicateKeyError` -> 409. No read first. |
| 13 | `punch_in` | `datetime.fromtimestamp(ms/1000)` uses the server's local zone, accepts seconds, floats, negatives, bools; `if body.punched_at` treats 0 as "not sent"; no range check. | Send `punched_at=1783312500` (seconds): silently a 1970 date. | `StrictInt` between 1e11 and 4102444800000 (else 422); `ms // 1000` -> aware UTC, truncated to whole seconds. |
| 14 | `punch_in` | `date = ts.date()` is the local calendar date, not the IST date, and ignores the overnight rule (R1). | 21:55 IST punch-in on a UTC server for a 22:00 shift lands on the wrong day; 03:00 punch-in of a night shift gets today's date. | `attendance_date()` converts to IST and applies the overnight rule. |
| 15 | `punch_in` | `status` is any string (`ABSENT`, `"banana"`). | POST `status="ABSENT"` returns 201 with punch times. | `Literal["PRESENT","WFH","ON_DUTY"]`. |
| 16 | `punch_in` | Stores naive datetimes and returns raw datetimes plus an `id` (the ObjectId as a string); contract forbids `_id`/`id`, wants epoch ms. | Look at the response. | `record_to_api()` builds the response: no id, instants in epoch ms, defaults filled. |
| 17 | `list_attendance` | `list(find(q))` loads the whole collection and sorts/paginates in Python: slow and memory-hungry at 100k records. No indexes at all. | 100k records: seconds per request, COLLSCAN in explain. | Sort/skip/limit in MongoDB, `count_documents`, compound indexes that match the filters and the sort. |
| 18 | `list_attendance` | Sort is by `date` only (no `emp_code` tie-break, so pages can repeat or skip rows); `page=0` gives a negative slice; `page_size` unbounded; invalid `status` and non-dates accepted; `date_from > date_to` not rejected; returns `id`. | `page=0`; `date_from=banana`. | Sort `date desc, emp_code asc`; validated params; 422 on bad or inverted dates; `_id` excluded. |
| 19 | `/health` | Always returns ok, even if MongoDB is down; the runner polls it to decide readiness. | Stop MongoDB, `/health` still 200. | Pings MongoDB, 503 on failure. |
| 20 | module level | `MongoClient` is naive (`tz_aware` off), so every datetime read back is naive and easy to mis-compare. No indexes created at startup. | Compare a stored datetime with an aware one: `TypeError`. | `tz_aware=True`; `ensure_indexes()` at startup (idempotent) and retried from `/health`. |

**Looked at and judged fine:** `load_dotenv()` (default `override=False`, so real environment variables win, as required); reading `MONGO_URI`/`MONGO_DB` from the environment; `doc.pop("_id")` after `insert_one` (needed because PyMongo adds `_id` to the dict); returning 201 from the create endpoints.
